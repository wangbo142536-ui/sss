## 测试用例

### TC-CTX-001 浏览器上传后解析主信息字段

目的：验证浏览器上传 Excel 后，页面能从文件顶部提取真实上下文字段并展示在主信息区。

步骤：
1. 使用浏览器打开 `/procurement/materials`。
2. 使用 `wangbo / 123456` 登录。
3. 上传 `E:\pro\haishi\tmp\quote_template_SPHT25SG005_R01.xlsx`。
4. 等待上传解析完成，查看页面顶部主信息区。

预期：
1. 主信息区出现并保持现有主信息卡片布局。
2. 展示字段和值分别为：船舶名称 `明丰轮/PACIFIC HARVEST`、询价单号 `SPHT25SG005-Q03`、物资类别 `Cabin Supply`、币种 `USD`、补给港口 `SHU LANG HU` 或字典等价值、预靠港时间 `2025-12-29`、收报单位 `CHINA MARINE SHIPPING AGENCY ZHOUSHAN COMPANY LTD.`、经办人/邮箱 `张国强 / mwta@cmhk.com`。
3. 页面不要求用户手工补录这些已能从 Excel 顶部识别出的字段。

### TC-CTX-002 字段值格式与等价值展示

目的：验证关键字段格式稳定，避免显示成原始噪音、空值或错误映射。

步骤：
1. 复用 TC-CTX-001 上传结果。
2. 逐项查看主信息字段显示文本。
3. 特别核对港口、时间、经办人和邮箱的格式。

预期：
1. 船舶名称完整保留中文名和英文名，中英文之间允许用 `/` 或页面既有等价分隔符，但不得丢失任一名称。
2. 询价单号精确为 `SPHT25SG005-Q03`，不得误取报价号或文件名。
3. 补给港口允许展示 `SHU LANG HU`，也允许展示数据字典匹配后的等价值；不得展示供应港口或报价侧港口。
4. 预靠港时间按日期语义展示为 `2025-12-29`，不得错成报价日期、上传日期或当前日期。
5. 经办人和邮箱同时展示，邮箱为 `mwta@cmhk.com`，不得被截断或与收报单位混淆。

### TC-CTX-003 不展示报价侧字段

目的：验证主信息区只展示询价上下文，不泄露或误展示报价侧字段。

步骤：
1. 复用 TC-CTX-001 上传结果。
2. 查看主信息区、展开态、悬浮提示和相邻摘要区域。
3. 搜索或人工检查是否出现报价侧字段名。

预期：
1. 主信息区不展示：总报价金额、报价号、报价日期、折扣、税率、减免金额、支付条款、有效期、供应港口、交付周期、船舶动态/代理资料、询价说明、报价说明。
2. 若这些字段存在于 Excel 原文件中，也只能作为原始模板或后续导出所需数据保留，不作为物料采购入口主信息展示。
3. 不得用空标签、`-`、`暂无` 等方式占位展示上述禁止字段。

### TC-CTX-004 保持现有主信息卡片样式

目的：验证新增字段不破坏已有主信息卡片视觉和交互。

步骤：
1. 使用浏览器上传测试 Excel。
2. 分别在常用桌面宽度和较窄宽度下查看主信息区。
3. 对比现有主信息卡片风格，包括卡片结构、字段标签、值样式、间距、换行和整体层级。

预期：
1. 新增字段融入现有主信息卡片，不新增突兀的独立大块、不改变页面主流程布局。
2. 长文本如收报单位、船舶名称、经办人/邮箱可完整阅读，允许合理换行或省略后提供完整提示，但不得与其他字段重叠。
3. 主信息区在字段增加后仍清晰可扫读，按钮、上传区、明细区不被遮挡。
4. 没有乱码、英文标签错位、字段值溢出卡片或横向滚动异常。

### TC-CTX-005 保存需求单后上下文字段回填

目的：验证从 Excel 顶部提取的字段能随需求单保存，并在重新进入页面或详情时回填。

步骤：
1. 上传测试 Excel，并确认主信息字段展示正确。
2. 保存物料需求单。
3. 记录生成的需求单号、询价单号或其他可定位标识。
4. 离开当前页面后，通过询价管理、比价管理或可回到该需求单的入口重新打开。

预期：
1. 保存成功后，需求单仍关联本次上传文件和提取出的上下文字段。
2. 重新打开后主信息区字段值保持一致：船舶名称、询价单号、物资类别、币种、补给港口、预靠港时间、收报单位、经办人/邮箱不丢失。
3. 页面不得回退到旧的手填默认值、空值、文件名推断值或 mock 值。
4. 禁止字段仍不得在回填后的主信息区出现。

### TC-CTX-006 生成比价时上下文字段传递

目的：验证点击生成比价后，询价上下文字段能传递到比价详情或相关链路。

步骤：
1. 上传测试 Excel 并保存需求单。
2. 点击生成比价或进入比价详情。
3. 在比价页面查看主信息、需求摘要或同等位置。

预期：
1. 比价详情能识别并展示与需求单一致的核心上下文字段，至少包括船舶名称、询价单号、币种、补给港口、预靠港时间。
2. 比价页面使用保存后的需求单数据，不重新从文件名、当前日期或报价侧字段推断。
3. 币种为 `USD`，金额展示逻辑若涉及美元，应符合页面既有 `$` 展示口径。
4. 不把报价侧字段传入比价主信息区展示。

### TC-CTX-007 导出报价模板回归

目的：验证新增顶部上下文字段解析不影响既有“原模板导出并回写报价列”的能力。

步骤：
1. 上传测试 Excel 并保存需求单。
2. 进入比价页，确保存在可导出报价模板的路径。
3. 执行报价模板导出。
4. 打开导出的 Excel，核对顶部上下文和报价回写区域。

预期：
1. 导出仍基于本次导入的原始 Excel 模板。
2. 顶部原有上下文结构不被破坏，船舶、询价单号、物资类别、币种、港口、预靠港时间、收报单位、经办人/邮箱仍在原模板对应位置或语义位置。
3. 只回写有效询价行的 `Quotation Price` 列。
4. `Item Discount(%)` 和 `Include tax rate(%)` 本期仍不处理、不导出填充。
5. 新增字段解析不得导致模板列错位、行错位、合并单元格损坏或导出失败。

3. 按白名单清理本次产生的需求单、比价记录、采购单、上传文件关联或临时导出文件。

预期：
1. 允许清理的白名单范围只包含本次测试产生的数据，建议以 `SPHT25SG005-Q03`、测试生成的 `demandId/demandNo/applicationNo/purchaseOrderNo/fileId` 为定位条件。

## 验收标准

1. 浏览器上传 `quote_template_SPHT25SG005_R01.xlsx` 后，主信息区展示 8 类真实上下文字段，字段值符合产品口径。
2. 主信息区保持现有主信息卡片样式，不出现布局破坏、重叠、溢出、乱码或无关大改。
3. 报价侧字段不在主信息区展示，也不以空占位方式展示。
4. 保存需求单后重新进入，已提取字段能稳定回填。
5. 生成比价后，比价链路可使用并展示必要上下文字段，且币种、港口、预靠港时间不被替换为报价侧或默认值。
6. 导出报价模板仍使用上传的原始模板，只回写有效询价行 `Quotation Price`，不新增处理折扣和税率列。
7. 测试数据清理必须按白名单执行，不影响基础库、账号权限、字典、SKU 池和历史验证数据。
8. 正式测试报告必须说明浏览器测试结果；如浏览器不可用，必须写明具体阻塞原因和替代核对方式。

## 风险与关注点

- Excel 顶部字段可能存在合并单元格、英文标签、中文标签或左右区域混排，测试需关注是否误取报价侧字段。
- 港口字段存在字典匹配场景，验收时允许 `SHU LANG HU` 与字典等价值，但必须能证明语义一致。
- 收报单位和值较长，容易造成卡片换行和遮挡问题。
- 询价单号与报价号相似，必须重点防止误取报价号。
- 导出回归必须关注模板结构，不能只看导出接口成功。
